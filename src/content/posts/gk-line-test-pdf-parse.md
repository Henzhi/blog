想做一个公考行测刷题系统，第一道坎不是技术架构，是**题从哪来**。

没有开放的题库 API，能找到的是 2000–2024 年国考 / 省考 / 选调的 PDF 合集，1.7GB，以扫描件为主。传统「OCR + 规则解析」的路子在这里基本走不通：行测题里有大量图形推理、资料分析表格、空间折叠题，纯文本 OCR 一上来就把信息丢了。

## 换个思路：让 VL 模型直接输出结构

既然题目本身是图文混排，那就用能看图的多模态模型来处理。流程是：

1. 把 PDF 按页切成图片；
2. 交给 VL 模型，要求它**直接输出 JSON**，而不是先 OCR 再解析；
3. 后端校验 schema，不合格的重试，仍不合格的进人工队列。

关键在 Prompt 把输出格式钉死：

```text
你是题库结构化抽取器。请从这一页图片中提取所有题目，严格按以下 JSON 输出：

[
  {
    "type": "言语理解 | 数量关系 | 判断推理 | 资料分析 | 常识判断",
    "stem": "题干原文",
    "options": {"A": "...", "B": "...", "C": "...", "D": "..."},
    "answer": "B",
    "explanation": "解析原文",
    "has_image": true
  }
]

要求：
- 题干含公式用 LaTeX 包裹
- 图中关键图形用文字描述补充到 stem 末尾
- 无法确定的字段填 null，不要编造
```

最后一条「不要编造」很关键。模型在答案缺失时倾向于猜一个，宁可让它返回 `null` 再人工补，也不要一条错的答案混进题库。

## 系统架构

后端 Java 栈，前端 Vue：

| 层 | 选型 |
| --- | --- |
| 后端 | Spring Boot 3.5 + Spring Security + JWT |
| ORM | MyBatis-Plus |
| 数据库 | MySQL 8 |
| 前端 | Vue 3 + Element Plus |
| 解析 | 通义千问-VL |

## 还没做完的

- 解析准确率还没做系统评测，计划抽样 500 题人工核对；
- 图形推理题的图没法结构化入库，目前只能存原图 + 文字描述；
- 错题本、组卷逻辑还没开始写。

这个项目节奏会慢一些，主要成本要摊在解析这一步上。
